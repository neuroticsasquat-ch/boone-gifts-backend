# MySQL to SQLite Migration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace MySQL with SQLite as the database backend for the Boone Gifts API.

**Architecture:** Swap the pymysql driver for Python's built-in sqlite3 module. Update SQLAlchemy engine configuration to handle SQLite's threading model and foreign key enforcement. Replace MySQL-specific Alembic migrations with a single fresh SQLite migration. No changes to routers, schemas, or application logic.

**Tech Stack:** SQLAlchemy 2.0, SQLite (stdlib), Alembic, pytest

> **Note:** Tasks 1–5 must all be completed before the project is functional. Do not attempt to run the application or tests until Task 4 is complete.

- [ ] **Step 2: Update database.py for SQLite**

Replace the full contents of `app/database.py` with:

```python
from sqlalchemy import create_engine, event
from sqlalchemy.orm import DeclarativeBase, sessionmaker

from app.config import settings

engine = create_engine(
    settings.database_url,
    connect_args={"check_same_thread": False},
)


@event.listens_for(engine, "connect")
def _set_sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA foreign_keys=ON")
    cursor.close()


SessionLocal = sessionmaker(bind=engine)


class Base(DeclarativeBase):
    pass
```

The `check_same_thread=False` is required because FastAPI serves requests across threads but SQLite connections default to single-thread mode. The event listener enables foreign key enforcement which SQLite disables by default.

- [ ] **Step 2: Update alembic/env.py**

Replace the full contents of `alembic/env.py` with:

```python
from logging.config import fileConfig

from sqlalchemy import create_engine, event

from alembic import context

from app.config import settings
from app.database import Base
from app.models import (
    User, Invite, GiftList, Gift, ListShare, Connection, Collection, CollectionItem
)

config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata


def run_migrations_offline() -> None:
    url = settings.database_url
    context.configure(
        url=url,
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
        render_as_batch=True,
    )

    with context.begin_transaction():
        context.run_migrations()


def run_migrations_online() -> None:
    connectable = create_engine(
        settings.database_url,
        connect_args={"check_same_thread": False},
    )

    @event.listens_for(connectable, "connect")
    def _set_sqlite_pragma(dbapi_connection, connection_record):
        cursor = dbapi_connection.cursor()
        cursor.execute("PRAGMA foreign_keys=ON")
        cursor.close()

    with connectable.connect() as connection:
        context.configure(
            connection=connection,
            target_metadata=target_metadata,
            render_as_batch=True,
        )

        with context.begin_transaction():
            context.run_migrations()


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

Key changes:
- Imports all 8 models (not just User and Invite) so autogenerate sees every table.
- Uses `render_as_batch=True` — required for SQLite since it doesn't support `ALTER TABLE` for most operations. Batch mode recreates tables instead.
- Uses `settings.database_url` directly instead of reading from `alembic.ini`.
- FK pragma event listener is on the engine (before `.connect()`) so it fires correctly.
